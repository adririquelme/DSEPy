# DSEPy Workflow Guide

DSEPy follows a three-stage workflow. Later stages depend on outputs generated by earlier stages.

```text
Point cloud + normals
        │
        ▼
1. Principal poles
        │
        ▼
2. DS classification
        │
        ▼
3. Spatial clustering
        │
        ├── Normal spacing
        ├── Persistence
        ├── Cluster Fisher analysis
        └── Cluster facets
```

## Stage 0 — Select and refresh the cloud

DSEPy reads the selected CloudCompare entity through `pycc`.

The source point cloud should contain valid normal vectors. Press **Refresh** after selecting or changing the CloudCompare entity.

The refresh operation determines which workflow actions and Tools commands can be enabled.

## Stage 1 — Principal poles

### 1. Colour-code 3DPC

The first block provides orientation-based colour mapping of the point cloud.

#### Pole calculation space

Two choices are available:

- **Original** — use the original normal orientations.
- **Rotated** — use normals transformed by the stored Normal Colour Optimisation rotation, when available.

The original point cloud is not modified; DSEPy creates a coloured copy.

#### Colour space

The available colour spaces are:

- HSV
- CIELAB
- CIELCH
- CIELCHmod
- OKLCH
- HSLuv

#### Value / lightness

For the colour systems that expose a lightness/value parameter, this controls the fixed lightness/value used for the colour mapping.

The **Generate colour-coded point cloud** button creates the CloudCompare copy.

### 2. Principal poles calculation

The Principal Poles block controls the density analysis and pole extraction.

The calculation includes:

- stereonet projection selection;
- density grid/bin level;
- minimum angular separation between retained poles;
- bandwidth selection;
- maximum number of principal poles;
- density visualisation;
- pole-table review and editing.

The automatically detected poles are candidates. The reviewed principal-pole table is authoritative for subsequent DS classification and clustering.

### Pole review

The pole table can be edited manually. Pole orientation changes should be made deliberately because DS classification and subsequent clustering use the reviewed pole list.

### Density visualisation

DSEPy can display the pole distribution and relative normal density on a stereonet. Depending on the selected settings, density can be displayed using contour lines or filled contours.

## Stage 2 — DS classification

Once principal poles have been reviewed, Step 2 becomes available.

DSEPy assigns point-cloud normals to discontinuity families according to their orientation relative to the reviewed principal poles and the configured DS cone threshold.

The resulting scalar field is:

```text
Discontinuity Set (DS)
```

The classified poles can also be plotted by family.

The DS field becomes an input to Stage 3.

## Stage 3 — Spatial clustering

Stage 3 uses the classified point cloud and performs spatial clustering within the discontinuity families.

Important parameters include:

- K-th neighbour (`K`);
- sigma multiplier (`k_sigma`);
- DBSCAN MinPts;
- minimum cluster size;
- coplanarity-merge threshold;
- orientation fixing using the family pole;
- cluster sorting;
- random seed;
- optional creation of separate cluster clouds.

The clustering stage produces the scalar field:

```text
Cluster id (cl)
```

and plane-related fields such as:

```text
A
B
C
D
```

for fitted cluster planes.

## Cluster Fisher analysis

DSEPy calculates directional statistics for cluster normals, including Fisher concentration-related quantities and maximum deviation/confidence measures.

The results can be displayed in a stereonet together with the cluster normals, mean poles and Fisher dispersion circles.

## Cluster facets

After plane fitting, DSEPy can generate planar meshes for valid clusters.

Available facet shapes include:

- convex;
- disk;
- ellipse;
- rectangle.

The resulting meshes are added to the CloudCompare database.

## Normal spacing

The Normal Spacing tool becomes available after the required DS/cluster information has been generated.

Spacing can be analysed by family and reported in metres.

## Persistence

The Persistence tool uses the classified/clustering results to analyse discontinuity persistence by family.

Results are reported in metres where applicable.

## Normal Colour Optimisation

Normal Colour Optimisation determines a rotation of the pole/normal reference system for orientation-based colour mapping.

The optimisation stores the resulting rotation and associated values so that the rotated pole space can subsequently be selected in the Stage 1 colour-coding block.

The optimisation can use two-angle or three-Euler-angle degrees of freedom depending on the selected configuration.

## Outputs in CloudCompare

Depending on the workflow, DSEPy may create:

- coloured point-cloud copies;
- principal-pole visualisations;
- DS scalar fields;
- cluster scalar fields;
- fitted-plane coefficients;
- separate family/cluster clouds;
- planar cluster facets.

The source cloud is not intentionally overwritten by the orientation-based colour export.

## Reproducibility

For reproducible research:

1. Keep the DSEPy release version used for the analysis.
2. Record the CloudCompare version and Python runtime.
3. Keep the DSE execution log.
4. Record the DSEPy method parameters.
5. Preserve the input point cloud and computed normals.
6. Avoid modifying the reviewed principal-pole table after DS classification unless the downstream results are deliberately recomputed.
